# 定位并修复缺陷

先读取[工作范围与交付证据](../../references/evidence.md)。用户要求修复时，完成已授权的代码、必要测试和验证；只要求解释或定位时保持只读。

建立能被反驳的假设：根据输入、日志、调用链和版本区分代码缺陷、配置错误、数据问题与环境故障。保存原始失败命令、执行目录、预期/实际结果。优先构造最小复现或失败的业务断言；已有失败测试足够时复用它。

追踪到导致错误的条件，检查相关调用方和边界。复现受限时说明哪些证据支持假设、哪些仍缺失；未经验证不能宣称根因确定。不把关闭超时、吞掉异常、忽略返回码或放松测试作为修复。

实现能解决根因的最小完整改动，沿用目标仓库约定。为有回归风险的行为补测试：优先断言用户可见结果、异常或持久化副作用，不只断言 mock 调用。修复后运行原始复现、相关测试和必要的构建。

在隔离副本中暂时回退自己的修复或注入代表性错误，确认回归测试确实失败，再恢复修复并通过；不要因此触碰用户未提交修改。无法进行反向验证时明确列为未验证。区分新引入失败与已有失败。

.NET 相关测试按需读取[存量项目验证](../../references/dotnet.md)。SDK/数据库不可用时保留日志并报告阻塞；可继续静态诊断或独立测试，但不能称修复已充分验证。

交付症状、根因证据、修改与回归结果。跨越公共契约或需要改变预期行为时说明权衡并确认缺失的业务决策；已有授权和明确的局部实现不重复审批。
