# 保持行为的渐进重构

先读取[工作范围与交付证据](../../references/evidence.md)。说明本次结构目标和触及范围，读取调用方与现有测试。按影响列出必须保持的契约：公共 API、序列化形状、状态码、异常类型、数值与排序、事务或外部副作用、取消与并发语义。只列相关项，不制作空泛清单。

修改前取得基线。缺少关键保护时先加入独立的行为断言，区分应保护行为与已知缺陷。已知缺陷可以单独提出，但不能在重构中默默改掉。业务决策不明确时先完成可独立的内部整理。

逐步改变结构，每一步保持可构建和可验证；用实际职责划分模块，不以文件行数或设计模式数量为目标。避免同时改框架、依赖版本、格式化全仓或扩大公共 API。

用相同输入、配置和外部契约对照修改前后结果；运行相关业务/消费者测试。必要时检查公共 API 签名、序列化、异常与持久化副作用。仅编译成功或 mock 次数相同不足以证明行为保持。

.NET 项目按需读取[存量项目验证](../../references/dotnet.md)。保留用户既有修改，实验在独立副本执行。交付结构变化、行为对照与兼容性证据；验证环境缺失时明确说明尚未证明哪些契约。
