# 为既有行为补可靠测试

先读取[工作范围与交付证据](../../references/evidence.md)。找到当前测试框架、数据准备、隔离与运行方式，沿用它们；不要为了偏好更换框架或引入额外容器。

从真实消费者和业务契约选择要保护的结果：输入输出、边界、异常、副作用、顺序或序列化。区分已确认正确的业务行为、尚待确认的历史行为和疑似缺陷。行为刻画记录现状但不能把明显错误永久定成规范；预期不清时报告差异，并继续验证无争议部分。

选择最低但足够的测试层：纯逻辑用单元测试，路由/DI/持久化语义用相关集成测试。mock 用于隔离昂贵边界，不让 mock 调用断言替代业务结果。时间、随机性和并发使用可控输入与有界等待，不依赖任意 sleep。

加入有代表性的正常、边界和失败案例；避免按私有实现逐行镜像。必要的测试接缝保持局部，较大的结构调整先说明范围。运行目标测试，确认非零发现数和实际断言结果。

在隔离副本中改变一个关键比较、取消传播或副作用，让新测试暴露代表性错误；保存失败证据，撤销变异后重跑。测试对同类错误无反应时改进断言，不用覆盖率数字掩盖。

.NET 项目按需读取[存量项目验证](../../references/dotnet.md)。交付所保护行为、测试命令/数量、变异结果及未覆盖边界；数据库不可用与零测试发现不能写成通过。
