# 评审指定变更

先读取[工作范围与交付证据](../../references/evidence.md)。固定范围：提交/分支解析为确切基线与目标 SHA；工作区区分 staged、unstaged 和相关 untracked 文件，保留差异快照及当前状态。范围不明确时结合上下文选择并说明；无法确定基线时询问缺失信息。

读取差异及必要上下文，沿受影响调用方、配置、测试和数据路径追踪行为变化。重点找由本次变更引入的可触发缺陷、兼容性问题与缺失的必要验证；历史问题只有被此次变更激活时才作为本次缺陷。

对候选问题寻找反证：既有保护、上层校验、有效条件配置、覆盖测试。可执行时运行针对性复现；仅静态证据时说明限制。普通风格偏好或未证实的猜测不升级为缺陷，不凑问题数量。

每项发现包含：优先级、最小准确文件/行位置、触发条件、用户影响、证据和可执行修复方向。没有可证实缺陷时明确说未发现，并报告验证范围及残余风险；测试未执行、环境不可用不能说检查通过。

.NET 项目按需读取[存量项目验证](../../references/dotnet.md)。默认只读，不产生代码修改或自动提交。用户随后要求“修复所有”时，进入已授权的修复与验证，不止重复报告；本插件的 [bugfix](../bugfix/SKILL.md) 可供此时读取，不预先执行其他流程。
