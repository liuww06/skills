## 适用场景

本技能是 invest 插件的汇总决策层：当用户已围绕某个标的（公司 / 行业 / 指数）收集或讨论了多维信息，希望汇总成「能不能投、投多少、怎么控风险」的最终结论时触发。
触发示例（中文）：「<公司名> 到底值不值得投，帮我综合多方空方给个结论」「<行业名> 我想建仓，仓位和止损怎么定」。
触发示例（英文）："Should I invest in <company>? Weigh the bull and bear case" / "How should I size this position and manage the risk on <index>"。
若用户只要单一维度分析（如纯财报解读、纯技术面），先引导到对应专项技能；本技能负责把各维度汇总成决策结论。

## 输入确认

1. 本技能必须先有标的（公司 / 行业 / 指数任一）才能执行；用户可同时附上已有观点、成本或持仓信息，这些只作「待检验的初始假设」进入多空论据表，不直接采信。
2. 若用户未提供任何标的：输出本技能的使用说明与分析框架概览，列出可分析的六个维度（信息汇总、多空论据表、反面论证、结论分级、仓位与风险框架、证伪条件与跟踪清单），并询问用户要分析什么标的。此情形下不发起联网检索。
3. 用户提供标的后，再按「数据检索 → 分析框架 → 输出模板」流程执行，任何情况下不得省略反面论证。

## 数据检索

1. 检索前先读共享数据源清单 `../../references/data-sources.md`（相对本技能文件的路径），并遵守 `../../references/analysis-conventions.md` 的引用格式与置信度分级。
2. 使用可用的联网搜索 / 网页读取工具（如 WebSearch / WebFetch）获取数据，不依赖本地脚本或付费数据接口。
3. 本技能核心来源优先级：
   - 本插件全部其它技能的产出（公司研究 / 技术分析 / 行业分析 / 板块分析 / 市场调研 / 宏观分析 / 国际局势 / 财报解读）：最高优先，直接引用其结论并标注来源技能。
   - 法定披露源与官方机构（巨潮资讯网、交易所、央行、统计局、美联储等）：关键数字以法定披露为准。
   - 主流财经媒体（东方财富、同花顺、财新、财联社等）；自媒体与论坛仅作线索，不作数字引用源。
4. 补充检索用 ../../references/data-sources.md 的全量来源清单与检索式模板。可直接执行的检索式示例：
   - `<公司名> 年报 业绩` / `site:cninfo.com.cn <公司名> 公告`
   - `<板块名> 资金流向 主力净流入`
   - `<指标名，如 CPI / PMI / 社融> 最新 同比`

## 分析框架

本技能是多技能的汇总决策层，工作流固定为：先引用其它技能结论，再决策。任一维度缺失时，引导用户先运行对应技能，或在本次会话现场检索补齐；不得凭记忆编造数据。

### ① 信息汇总

- 逐维度归集：公司研究（基本面与估值）、技术分析（趋势与关键位）、行业分析（景气与格局）、板块分析（板块轮动与资金流向）、市场调研（大盘环境与市场情绪，作为仓位框架的市场背景输入）、宏观分析（宏观与流动性）、国际局势（地缘与政策风险）、财报解读（最新业绩）。
- 每条信息标注来源（技能产出或站点）与数据日期；区分「事实」（有来源）与「分析」（推断），推断处使用「判断 / 推测」字样。
- 交叉核对不同技能结论之间的矛盾（如基本面看多而技术面走弱），矛盾处并列呈现，不擅自取舍。
- 警惕确认偏误：空方证据必须与多方证据同等力度检索，不得只找支持结论的信息。

### ② 多空论据表

- 多方论据与空方论据逐条对照列出，每条标注来源与置信度（确认 / 大概率 / 存疑）。
- 判断时看论据的质量与可验证性，而非数量；权重向有 ≥2 个独立来源支撑的论据倾斜。
- 警惕把单一来源传闻、无日期旧数据、情绪化表述当作强论据。

### ③ 强制反面论证（devil's advocate）

- 本节必填不可省略：假设当前结论是错的，列出最可能的反驳理由与被忽略的风险。
- 逐条回答：哪个数据或逻辑一旦被推翻，结论就不再成立？
- 警惕走过场：只写「政策有不确定性」这类空话没有价值，反面论证必须指向具体变量与数据。

### ④ 结论分级

- 结论三选一：看多 / 中性 / 看空；置信度三级：确认（≥2 个独立来源交叉验证一致）/ 大概率（单一可靠来源或有佐证）/ 存疑（来源单一或存在分歧）。
- 说明主要依据：列出支撑结论的前 2-3 条关键论据，并注明其中任何一条失效时结论如何调整。
- 警惕：置信度「确认」只授予交叉验证过的关键事实，不授予综合判断本身；综合判断最高标「大概率」。

### ⑤ 仓位与风险框架（仅框架性参考）

- 分批思路：给出示例性框架，如「首次建仓 <比例区间>、关键假设验证后加至 <比例区间>、证伪信号触发时退出」，具体比例由投资者自行决定。
- 单标的风险预算：先定风险再定仓位——单一标的占组合的比例上限、单笔最大可接受亏损额，二者先于买入数量确定。
- 止损与止盈参考框架：以「证伪条件触发」或「关键假设变化」作为调整依据，而非拍脑袋的固定百分比。
- 合规红线：一律不给具体买卖指令、目标价或收益承诺；相关内容仅以「框架性参考」表述，最终决策由投资者自行作出。

### ⑥ 证伪条件与跟踪清单

- 证伪条件：写出出现什么信号说明本判断错误（如 <关键财务指标> 低于 <阈值>、<行业或政策变量> 反转、跌破 <技术关键位>），并给出触发后的框架性应对思路。
- 跟踪清单：列出需持续跟踪的事件与数据（财报披露窗口、行业数据发布、政策会议、地缘事件），每条注明目的是验证哪条论据。
- 警惕：没有证伪条件的结论等于不可检验的结论；跟踪清单聚焦 3-6 条关键项，过长等于没有重点。

## 输出模板

按以下 markdown 骨架输出完整报告，逐节填写，不得遗漏章节；各节用 <占位符> 标注待填内容：

```markdown
# <标的名称> 投资决策报告（截至最新可得数据）

## 一、决策摘要
- 结论：<看多 / 中性 / 看空>；置信度：<确认 / 大概率 / 存疑>
- 核心逻辑：<用 2-3 句概括多方与空方最主要论据>
- 关键风险：<当前最需要盯住的一条风险>
- 数据基础：<引用了哪些技能产出与检索来源>

## 二、多空论据表
| 方向 | 论据 | 来源 | 置信度 |
| --- | --- | --- | --- |
| 多方 | <多方论据> | <技能或站点，YYYY-MM-DD> | <确认 / 大概率 / 存疑> |
| 空方 | <空方论据> | <技能或站点，YYYY-MM-DD> | <确认 / 大概率 / 存疑> |

## 三、反面论证（devil's advocate）
- 假设结论错误，最可能的反驳：<反驳理由>
- 被忽略的风险：<风险点>
- 结论对哪条论据最敏感：<论据及其失效后果>

## 四、结论与置信度
- 结论：<看多 / 中性 / 看空>；置信度：<确认 / 大概率 / 存疑>
- 主要依据：<前 2-3 条关键论据及来源>
- 若主要依据失效，结论如何调整：<调整方向>

## 五、仓位与风险控制框架（仅框架性参考，非买卖指令）
- 分批思路：<建仓 / 加仓 / 退出的框架性条件>
- 单标的风险预算：<占比上限与单笔可接受亏损的设定思路>
- 止损与止盈参考框架：<基于证伪条件或关键假设变化的框架性表述>

## 六、跟踪与证伪清单
| 跟踪项 | 类型 | 验证目的 | 触发后的应对（框架性） |
| --- | --- | --- | --- |
| <事件或数据> | <证伪条件 / 持续跟踪> | <验证哪条论据> | <框架性应对思路> |
```

## 引用与时效

- 每个关键数字标注来源与日期，格式：`来源：东方财富（URL 或页面名，YYYY-MM-DD）`；页面无日期时写「日期未标注，未核实」。
- 关键数字须 ≥2 个独立来源交叉验证；无法核实的一律标注「未核实」，不猜测、不拼凑。
- 行情类数据波动快，报告统一表述为「截至最新可得数据」，不写死具体日期、价格与点位。
- 结论按 确认 / 大概率 / 存疑 三级标注置信度，授予标准遵守 ../../references/analysis-conventions.md 的定义。
- 不同来源数据矛盾时并列列出并说明分歧，不擅自取舍。
