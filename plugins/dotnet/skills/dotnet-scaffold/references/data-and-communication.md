# 按需数据与通信能力

先确认必须的产品/协议和用途；没有需求不增加依赖。用户已指定技术栈时遵循它。版本从官方文档/包元数据确认，并检查 SDK、TFM、许可证及平台兼容性。

| 能力 | 生成边界 |
|---|---|
| 数据访问 | 数据库类型未指定且无法推断时询问；按需求选择驱动/ORM，连接由配置注入，不编造表与领域模型 |
| 认证 | 确认身份提供方、客户端/服务端边界与认证方式；使用受支持集成，不用假 token 验证器 |
| 缓存 | 明确缓存对象与一致性需求，再选进程内或分布式；不因“高性能”默认引入 Redis |
| 消息 | 明确 broker、契约及消费方式；需要时设计取消、失败处理和幂等，不生成未定义的业务事件 |
| HTTP/gRPC | 仅存在协作需求才加入；HTTP 优先 IHttpClientFactory，传递取消与超时；重试考虑幂等性 |
| 观测 | 默认内置日志；明确需要 traces/metrics 时再加入 OpenTelemetry 和具体 exporter |

Clean Architecture 的实现依赖放 Infrastructure，业务接口放适当内层，宿主组合根注册。简单应用可留在同一项目，不为可选数据库强制切换架构。

服务端密钥通过 user-secrets/环境或部署秘密注入；NuGet 源凭据不写入仓库。Blazor WASM 和桌面分发产物不能保存服务端秘密。开发内存实现只能明确标识为开发用途，不默认为可部署持久化方案。

仅生成用户选择能力的连接配置和注册；外部系统不可访问时报告该集成未验证，不能将宿主启动成功视为集成通过。
